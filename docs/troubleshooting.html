Troubleshooting

Common issues encountered while configuring, running, or contributing to the ATE Social Survey Workflow, and how to resolve them. If your issue isn't listed here, open an issue on GitHub.

Configuration & EarthRanger Connection

The run fails straight away with no events returned

get_events fetches only atequestionnaire_rep events and uses raise_on_empty: true. If no survey events fall within the selected time range, the run stops instead of producing an empty dashboard. Widen the time range, and check that the EarthRanger account you connected can see that event type.

Authentication or connection errors at run time

EarthRanger credentials aren't checked when you save the data source, only when the workflow runs. Re-enter the URL, username, and password under Data Sources.

Download errors for .gpkg or .docx files

The Amboseli map layers and the Word template are downloaded from Dropbox during each run (3 retries). The runner needs internet access, and the Dropbox links in spec.yaml must still be shared publicly. If a link has been revoked, upload the file again and update the url in the matching fetch_and_persist_file task.

No grouping, base map, or map layer options in the form

This is expected. Groupers are fixed to [], and the base maps, Amboseli layers, and report template are all set in spec.yaml. The form only asks for workflow details, a time range, and an EarthRanger connection.

Survey Data & Charts

Fewer respondents than expected

Three filters run before any charting: serial number 46283 is dropped, only respondents older than 18 are kept (gt 18, so 18-year-olds are excluded), and only households with more than one person are kept. These filters run before missing values are filled, so rows with a blank age or household size are dropped too.

A chart, its PNG, or its dashboard widget is missing

Every task skips if its input is empty (any_is_empty_df) or an upstream task was skipped (any_dependency_skipped). Common causes:

  • Renamed questions. If a question heading changes in EarthRanger, the rename in map_survey_columns no longer matches (it uses raise_if_not_found: false, so there's no error). The chart that expects the English column name is then skipped. Update the rename map.
  • No dogs or no donkeys. Households with 0 dogs or 0 donkeys are filtered out of those two charts, so the chart is skipped if nobody in the period owns one.

Dog or donkey bar chart labels look wrong

Those two charts use hard-coded bin labels (0, 0 - 1, 1 - 2, 2 - 4, 4 - 8 for dogs; 0, 0 - 3, 3 - 7, 7 - 25, 25 - 56 for donkeys) that were set from an earlier data distribution. The natural-breaks bins are recalculated on every run, so with new data the labels may no longer match the real ranges. Update the labels in dog_bins / donkey_bins, or switch them to label_ranges: true.

Marital status shows unexpected categories or "No Response"

Marital status is typed as free text. replace_marital_status maps about 90 known spellings (English and Maa) to Married, Single, or Divorced. Any new spelling passes through unchanged and appears as its own category. Add it to the value_map. Widowed is mapped to Single and Separated to Married, and both are judgment calls you may want to revisit.

Sentiment & Statistics

Sentiment scores look lower than the answers suggest

I Don't Know and No Response score 0 and are included in the mean of the 9 statements. A respondent who skips several statements is pulled towards the negative end of the scale. See the scoring table.

Attitude map points are grey, or the legend shows ranges like "1 - 2" instead of labels

Sentiment bins use equal_interval with k = 5, fitted to the observed range of scores. The bins are then renamed only if their labels come out exactly as 0 - 1, 1 - 2, 2 - 3, 3 - 4, 4 - 5. When the observed range is narrower (for example 1.4–4.6), the labels differ, stay unmapped, and are drawn in the default grey #cfcfc4. Fixed bin edges of 0–5 would avoid this.

A Tukey plot is missing or errors

Tukey HSD needs at least two groups with more than one respondent each, after No Response is removed. With a short time range, a factor such as marital status or education may have too few respondents in some groups. Widen the time range.

Where is anova_results.csv?

The ANOVA step from the previous version of this workflow has been removed. Sentiment is now compared with boxplots, Tukey HSD plots, and scatter plots with an OLS trendline.

Maps, PNGs & Word Report

Map PNGs are blank or missing base map tiles

Map screenshots wait 40 seconds for ArcGIS tiles to load. On a slow connection this may not be enough. Increase wait_for_timeout in the three convert_*_map_png tasks.

The Word report is missing some or all charts

generate_survey_report embeds whatever PNGs are in the results folder when it runs. It doesn't wait for the PNG conversion tasks, which aren't its inputs in the task graph. In a parallel (async) run, the report can therefore be built before the PNGs exist. Run sequentially, or make generate_survey_doc depend on the convert_*_png tasks. The report also matches images by file name (e.g. {{ gender_of_participant_pie_chart }}), so renaming a chart's filename in spec.yaml leaves an empty slot in the template.

The report's demographic table is empty

The report looks for demographic-data.parquet (or .csv) in the results folder. If persist_demo_table was skipped or its filename was changed, the table is left empty.

Contributing & CI

These apply if you're modifying the workflow itself (spec.yaml or the generated ecoscope-workflows-social-survey-workflow/ directory) and opening a pull request.

Tests fail on test-cases.yaml parameters

The current test-cases.yaml is still the template placeholder: it passes a calculator parameter and sets groupers, but this workflow has neither and needs an EarthRanger connection. Replace it with at least one real case that sets workflow_details, time_range, and er_client_name.

Found wildcard version (*) in requirements or Found local file channel (file://) in requirements

Every dependency under requirements in spec.yaml must pin a version (or range) and use a remote conda channel. Wildcard versions and local file:// channels only work for local development.

VERSION.yaml (...) must be greater than main branch (...)

Bump MAJ/MIN/PATCH in ecoscope-workflows-social-survey-workflow/VERSION.yaml so it's strictly greater than the version on main.

Generated workflow directory differs from spec.yaml

Recompile with wt-compiler and commit the result:

pixi run --manifest-path pixi.toml --locked bash -c "./dev/recompile.sh --update"

No outputs written / can't find results

All outputs go to the directory in the ECOSCOPE_WORKFLOWS_RESULTS environment variable. Confirm it's set and that the workflow process can write to it.

The technical guide PDF is out of date

Regenerate it after changing spec.yaml (requires reportlab). The script writes the PDF to technical_guide/ and to docs/assets/:

python3 technical_guide/generate_technical_guide.py
